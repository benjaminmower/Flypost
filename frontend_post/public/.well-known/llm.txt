# Flypost Post - Write/Publish API (llm.txt v2)

service_name: Flypost Post
service_purpose: >
  Flypost Post provides authenticated write access to publish events.
  It parses natural-language event descriptions into structured Schema.org Event objects,
  validates them, computes integrity hashes, and stores them.

primary_audience: machine-agents (LLMs, AI assistants with write capabilities)
human_audience: developers building event publishing applications, real estate agents, brokerages

base_url: https://api.goflypost.com
canonical_openapi: https://api.goflypost.com/openapi.json

## Core Publishing Endpoints

### POST /api/parse-and-publish
Description: >
  Parse a natural-language event description using AI, validate it against the schema,
  enforce required geo/time constraints, compute an integrity hash, and store it.
  Returns the stored event with Flypost metadata.

Authentication: REQUIRED (proxy-enforced)
  - Browser (https://post.goflypost.com, https://app.goflypost.com):
      Authorization: Bearer <firebase_id_token>  (Firebase required; static tokens not accepted)
  - Machine/server-to-server (no origin / non-browser origin):
      Provide a static write token either as:
        - x-flypost-write-token: <token>   (recommended), OR
        - Authorization: Bearer <token>    (also accepted)
    The proxy maps the token to a brokerageId and injects x-flypost-brokerage-id.

Request Body (JSON):
  naturalLanguageInput: string (required) - Raw event description
  text: string (optional alias)
  input: string (optional alias)
  userContext: object (optional) - Additional metadata about the caller/channel
  brokerageId: string (optional) - Usually injected from token by the proxy (header takes precedence)

Important Requirements / Enforcement (server-side):
  - Provide clear what/where/when (type/category, address, date, and time window)
  - Geo coordinates are required for publishing:
      - The server will attempt geocoding from the address; if geocoding fails, it returns 400.
  - For open houses, endDate is required (time-gating + presence integrity)

Response Shape:
  success: boolean
  data:
    eventId: string
    event: FlypostEvent object (Schema.org Event + Flypost metadata + hash)
    processing:
      parsed: boolean
      validated: boolean
      hashed: boolean
      stored: boolean

Error Responses:
  - 400: Validation or enforcement error (missing/invalid fields, missing geo, timezone requirements)
  - 401: Authentication required (missing/invalid credentials)
  - 500: Internal server error

### POST /v1/events/upsert
Description: >
  Structured ingestion endpoint for machine sources (MLS, calendar, scraper, adapter).
  Validates the provided event object, strips forbidden Layer-2 fields, computes identity,
  upserts by identity, computes hash, and stores.

Authentication: REQUIRED (same policy as above)

Request Body (JSON):
  event: object (required) - Full Schema.org Event object (Flypost extensions allowed)
  source: object (optional) - { sourceType: string, sourceId?: string, sourceUrl?: string }

Response Shape:
  success: boolean
  operation: string ("insert" | "update")
  data:
    eventId: string
    eventIdentity: string
    updateCount: number
    event: FlypostEvent object

## Non-goals / Not supported here
- Presence check-ins and feedback submissions are "truth-writing" endpoints and are restricted to the Presence app origin.
  Do not attempt to call:
  - POST /v1/presence/*
  - POST /v1/feedback/*

## Security Notes
1. Never expose write tokens in client-side code
2. Always use HTTPS for API calls
3. Do not log tokens
4. Report security issues to security@goflypost.com
